# Company Domain Thesis

## The Product

The canonical vending machine for small pieces of verified reality that aren't worth an agent figuring out itself.

## The Thesis

Never sell reasoning an agent already owns. Sell observations, integrations, execution, decisions and proofs that are cheaper to buy than reproduce.

## The Category

Things an agent could theoretically figure out, but would irrationally spend time/tokens/integration effort figuring out when a trusted machine can answer for $0.003.

## What the Domain Must Communicate

To an agent (not a human), the domain must instantly signal:

1. **Trustworthy** — this is a reliable source of truth
2. **Verification** — this proves things, not opinions
3. **Simplicity** — one call, one answer, no integration hell
4. **Evidence** — returns receipts, timestamps, provenance
5. **Machine-native** — built for agents, not humans browsing

## The $0.003 Test

A capability is a strong micro-payment candidate if it satisfies at least 3 of:
- Fresh (answer changes over time)
- External (answer cannot be generated from the prompt alone)
- Annoying (reproducing it requires several operations)
- Deterministic (clean machine decision)
- Expensive to be wrong (mistakes create retries/loss)
- Low-frequency per agent (not worth implementing locally)
- Composable (result feeds into another action)
- Evidence-producing (you can prove why)
- Data-generating (every call improves a dataset)

## The Product Envelope

Every capability returns:
```
INPUT → DECISION → EVIDENCE → FRESHNESS → CONFIDENCE → COST → PROVENANCE → RECEIPT
```

## The Capability Ladder

```
L0: registry lookup       → FREE
L1: reality checks        → mostly FREE
L2: decisions             → $0.001-0.003
L3: historical intelligence → $0.01+
```

## Domain Requirements

- .com TLD
- Short (< 12 chars ideal)
- No hyphens, no numbers
- Works as a verb or clear noun
- Phonetically unambiguous
- Agent-interpretable (semantically transparent)
- Conveys: trust + verification + simplicity
